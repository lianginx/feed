# 文章列表分页与刷新计划

## 1. 当前上下文

### 文章列表

文件：`src/renderer/windows/main/components/ArticleList.vue`

- 使用 `@tanstack/vue-virtual` 虚拟列表。
- `articles` 来自 `useArticles()`。
- 订阅源、分类、未读、星标、今天等筛选条件变化时，会清空当前文章、滚动到顶部并重新查询。
- 当前虚拟列表索引直接对应 `articles` 数组索引。
- 当前底部固定显示“已经到底了”。

### 文章加载

文件：`src/renderer/windows/main/composables/useArticles.ts`

- `loadArticles()` 调用 `window.api.articles.list()`。
- 查询结果直接覆盖 `articles.value`。
- `reloadScope()` 根据当前订阅源、分类和筛选条件重新加载列表。
- 当前没有分页状态。
- `loading` 只负责延迟显示加载骨架，不负责请求防重入。

### 主进程查询

文件：`src/main/ipc/articles.ts`

- 当前排序为 `published_at DESC, id DESC`。
- 当前固定使用 `LIMIT 500`。
- 支持订阅源、分类、未读、星标、今天和搜索条件。

### 刷新事件

相关文件：

- `src/main/services/refresher.ts`
- `src/preload/index.ts`
- `src/preload/index.d.ts`
- `src/renderer/windows/main/composables/useFeedsEvents.ts`

刷新完成事件已经包含 `feedId`、`inserted`、`updated` 和错误信息。

## 2. 分页方案

### 2.1 使用游标分页

不要使用 `OFFSET`。继续保持 `published_at DESC, id DESC` 排序，并使用上一页最后一篇文章的发布时间和 ID 作为下一页游标。

需要正确处理 `published_at` 为空的文章，保证分页不重复、不遗漏。

接口需要支持：

- 每页大小；
- 上一页游标；
- 当前筛选和搜索条件；
- 当前页文章；
- `hasMore`；
- 下一页游标。

### 2.2 前端分页状态

`useArticles` 需要维护：

- 当前文章列表；
- 当前查询条件；
- 当前分页游标；
- 是否还有更多数据；
- 是否正在加载下一页；
- 是否正在刷新第一页。

筛选条件、搜索关键词或订阅源范围变化时，清空文章和游标，重新加载第一页并滚动到顶部。

加载下一页时追加文章，并根据文章 ID 去重。

### 2.3 滚动加载

滚动接近底部时加载下一页。需要避免同一页重复加载、没有更多数据时继续请求，以及旧查询返回后污染新查询结果。

## 3. 文章刷新策略

### 3.1 按滚动位置决定是否重载列表

前台和后台使用同一套逻辑，只关注文章列表是否在顶部。可使用小幅滚动阈值判断是否为顶部。

### 3.2 当前视图相关性

- 当前显示订阅源 B、刷新 A：不重载文章列表，也不增加当前列表的新文章提示。
- 当前显示订阅源 B、刷新 B：顶部时重载第一页，非顶部时显示新文章提示。
- 当前显示分类或全局列表：属于当前范围的订阅源刷新完成后参与更新；其他范围不影响当前列表。
- 未读、星标、今天等筛选条件必须纳入当前视图范围判断。

### 3.3 列表在顶部

每个相关订阅源刷新完成后立即重载文章列表第一页，不做防抖、不等待其他订阅源完成。每次重载都重置分页并保持在顶部，同时清除新文章提示。

### 3.4 列表不在顶部

订阅源刷新完成后不重载文章列表，根据刷新事件中的 `inserted` 数量累计新文章数量，并在列表顶部显示“有 N 篇新文章”。

点击提示后：

1. 清空分页状态；
2. 重新加载第一页；
3. 滚动到顶部；
4. 清除提示数量。

刷新失败时不增加数量、不重载文章列表，并保留已有列表。

## 4. 虚拟列表与按天分组

### 4.1 保留虚拟列表

虚拟列表继续负责减少 DOM 数量，分页负责减少单次数据加载量，两者同时保留。

### 4.2 日期分组

不要继续让虚拟列表索引直接对应文章数组。将数据转换为扁平行列表，行类型包括日期标题和文章行。

日期按本地日期生成，继续使用项目现有的 `dayjs` 工具。

日期行和文章行必须使用可区分的稳定 key。文章点击、右键菜单、已读和星标操作继续以文章 ID 为准。

### 4.3 行高与底部状态

日期标题和文章卡片高度不同，需要分别设置估算高度，并在必要时使用动态尺寸测量。

底部根据状态显示：

- 加载下一页：加载状态；
- 还有更多：不显示“已经到底了”；
- 没有更多：显示“已经到底了”。

## 5. 筛选与搜索

未读、星标、今天目前都是后端筛选，不是对已加载文章做前端筛选。分页后必须将这些条件传给每一页查询。

搜索同样由主进程查询数据库，也需要处理分页或明确的结果上限。推荐与普通列表共用分页机制。

搜索关键词变化时重置分页、重新加载第一页并清除新文章提示。旧搜索请求不得覆盖新关键词结果。

## 6. 请求并发策略

不需要对所有文章列表请求做全局防重入，也不做刷新防抖。

需要保证：

- 同一时间只加载一个下一页；
- 筛选条件或搜索关键词变化后，旧请求不能覆盖新结果；
- 旧分页请求不能追加到新的查询结果；
- 顶部状态下每个相关订阅源完成后可以立即刷新列表。

重点是防止旧响应污染当前状态，而不是限制所有刷新请求。

## 7. 推荐实施顺序

1. 主进程文章接口增加游标分页和 `hasMore`。
2. 更新 preload 的文章列表参数和返回类型。
3. 在 `useArticles` 中增加分页状态和第一页刷新逻辑。
4. 实现滚动到底部加载下一页。
5. 调整筛选和搜索，使其重置分页。
6. 根据文章列表滚动位置调整 `useFeedsEvents` 的刷新行为。
7. 增加顶部新文章提示。
8. 将虚拟列表改为日期标题行与文章行混合渲染。
9. 更新底部加载状态和“已经到底了”状态。
10. 处理旧请求返回、分页重复加载和刷新失败。
11. 运行类型检查和代码规范检查。

## 8. 验收场景

- 单个订阅源、分类和全局列表都能分页加载。
- 切换未读、星标、今天后从第一页重新加载。
- 搜索和清除搜索后分页状态正确重置。
- 当前显示 B 时刷新 A，不重载 B 的文章列表。
- 当前显示 B 时刷新 B，顶部立即重载，非顶部显示新文章提示。
- 分类或全局列表中，相关订阅源完成后逐个更新。
- 点击新文章提示后回到顶部并重新加载第一页。
- 后台和前台使用相同的顶部判断。
- 旧请求不能覆盖新筛选或搜索结果。
- 日期标题在分页边界处不重复、不丢失。
- 没有更多数据后不再请求。
- 图片加载后虚拟列表高度正常。
- 刷新失败时已有文章和分页状态不被破坏。
